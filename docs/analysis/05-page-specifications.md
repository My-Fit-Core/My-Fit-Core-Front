# 화면 명세 및 사용자 흐름

- 분석일: 2026-11-24
- 출처: Figma 최종 디자인 `2:6` 전체 메타데이터, 기존 사용자 담당 화면 54개의 `get_design_context`; 와이어프레임 `2:5`는 흐름 비교용
- 기준: 최종 디자인 추적 대상 Frame **81개** = 375×812px 화면·상태 79개 + 개발 설명 보드 2개(`418:10414` 370×812px, `403:10251` 394×812px). 착용 아이템 선택 페이지 팀원 담당안을 기준으로 사용자 담당 화면·상태 **44개**(스플래시·로그인 2, 마이페이지 14, 디지털 옷장 28). 독립 React Page 파일 수가 아니다.
- 기존 분류 사용자 화면·상태 Frame 54개는 이전 분석에서 `get_design_context`로 조회했다. 이번 재분류 후 사용자 담당은 44개다. 설명 보드 2개는 이번에 `get_design_context`로 조회했다. 시각 스크린샷은 대표 6개(400:10244, 400:10266, 418:10290, 607:10857, 739:12525, 873:14042)를 별도 검증했다. Prototype 연결과 일부 반응형 제약은 추가 확인 필요.

## 스플래시·로그인

**2026-11-27 작업 브랜치 구현 현황:** `/`와 `/splash`에서 1.5초 후 `/login`으로 이동한다. 로그인은 Mock 기본·로딩·성공·실패·취소를 처리한다. 로그인 본문에는 현재 Figma 원본에서 확인한 A2Z ExtraLight 16px를 사용한다. 첨부한 스플래시·로그인 SVG와 크롬 MyFitCore 워드마크를 적용했다. 카카오 기본 버튼은 공식 SVG를 사용하며 로딩 중에는 해당 SVG의 심볼과 Figma 상태 문구를 표시한다. 실제 인증 및 성공 후 이동은 후속 작업이다. [검수 경로와 에셋 출처](../../README.md#스플래시-및-로그인-검수-login-001)

아래 화면별 제안과 완료 기준은 최초 분석 이력이다.

### 스플래시 `400:10244`

**사실:** 흰색 375×812px 화면, 중앙 이미지 원본 `440:1689`(214×225px)과 MAPIKO 35px A2Z SemiBold wordmark, 하단 OS 홈 인디케이터 샘플. Figma 안에 로딩 표시 또는 타이머 수치는 없다. 로고 문구는 과거 Figma에 `PROVISIONAL`로 표기된다. **최신 사용자 결정:** 로고 디자인 확정; 실제 SVG 파일은 저장소에서 확인되지 않았다.

**제안:** `/splash`, `src/pages/splash/SplashPage.tsx`. 앱 시작 시 인증 판별 상태를 보여준 뒤 로그인/온보딩/홈으로 이동. 초기 `/`의 `/home` 직행은 정책 확정 후 변경. 비동기 확인 완료 전에 화면 깜빡임·리다이렉트 루프를 막는다. 모바일 네이티브 splash는 별개다. Mock 인증은 개발 모드에서만 사용한다.

**완료 기준:** 첫 진입/재진입, 미인증/인증·온보딩 여부 분기, 로딩 중 표시, 실패 시 복구 경로, 다양한 화면 높이에서 로고 유지. **미확정:** 확정된 로고 SVG 2종의 저장소 전달·배치, 인증 지속성, 네이티브 splash.

### 로그인 `400:10266`

**사실:** 24px 좌우 여백, 상단 150px부터 Hero Copy(A2Z 35px, 두 줄, gap 14px), 설명 Noto Sans KR 15px, 이미지 `397:1583` 328×246px(상단 353px), Kakao 버튼 `403:10252` 327×56px(상단 690px), OS 상태/홈 인디케이터 시각 샘플.

**제안:** `/login`, `src/pages/login/LoginPage.tsx`; 버튼 클릭 → pending → 성공/실패/취소로 분기, 중복 제출 금지. Figma 설명 보드에는 기존 사용자 성공→홈, 신규 사용자 성공→온보딩이 명시된다. 신규/기존 및 온보딩 완료 판별은 백엔드·온보딩 담당자 합의 후. 지금은 Mock 동작과 실제 OAuth 호출을 분리한다. Kakao 공식 아이콘/SDK/redirect URI와 모바일 앱 복귀 경로는 미확정. 카카오 제공 로그인 동의를 우선 활용하되 독립 약관 React Page는 이번 범위에 추가하지 않는다. 서비스 자체 약관 동의 방식과 카카오싱크는 연동 시 확인한다.

**완료 기준:** 기본·로딩·실패 인라인 문구(“로그인하지 못했어요”/“잠시 후 다시 시도해 주세요.”)·취소 복귀, 중복 클릭 방지와 접근성, 가로 320px 및 키보드/작은 높이에서 버튼 노출. 실제 인증 완료로 보고하지 않는다.

## 화면 전환·API·모바일 경계

```text
[구현 제안] / → /splash → (미인증) /login
                         → (인증) 온보딩 완료 확인 → /onboarding 또는 /home
/closet → 등록 → 사진 확인 → AI 분석 → 검수 → 저장 → 옷장/상세
/mypage → 프로필·추구미·아카이브·알림 또는 로그아웃/탈퇴
```

실제 Prototype 연결을 확인하지 못했으므로 이 흐름은 라우트 확정안이 아니다. API 엔드포인트·요청/응답 타입은 문서에 만들지 않는다. 12월 2일까지는 Mock 화면/인터랙션, 12월 3~10일에는 백엔드 명세가 나온 뒤 통합한다. OS status/home indicator, 카메라/갤러리, 시간 피커, OAuth 복귀는 모바일 패키징 결정과 실기기 검증이 필요하다.

## 2026-11-24 설명 보드와 담당 범위 보정

- 로그인 설정 보드 [`403:10251`](https://www.figma.com/design/XhhPLJSwkdCMAJgzqFLELf/마피코?node-id=403-10251)는 394×812px 개발 설명 보드다. 기본 Kakao 버튼, 인증 중 중복 클릭 방지, 실패 인라인 UI, 취소 시 로그인 복귀, 기존 사용자 홈/신규 사용자 온보딩 분기를 명시한다. 과거 텍스트 로고 임시 사용 문구는 로고 확정 결정으로 대체한다.
